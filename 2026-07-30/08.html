What Happens When Multiple Users Hit Your API at the Same Time?

Real World Java · 5 min read
원문 보기 (Medium)

요약

1000명이 동시에 API를 호출해도 스프링 부트는 인스턴스를 늘리지 않고 스레드로 승부한다.

여러 사용자가 동시에 스프링 부트 API를 호출하면 애플리케이션이 복제되는 것이 아니라, 내장된 톰캣이 요청마다 별도의 워커 스레드를 배정해 처리한다는 점을 쉬운 비유로 설명하는 글이다. 컨트롤러와 서비스, 리포지토리 같은 빈은 기본적으로 싱글턴이라 단 하나의 인스턴스를 모든 스레드가 공유하지만, 지역 변수는 스레드마다 독립적으로 유지되기 때문에 사용자 데이터가 서로 섞이지 않는다. 다만 싱글턴 빈에 상태(예: 카운터 값)를 저장하면 여러 스레드가 동시에 값을 변경하면서 레이스 컨디션이 발생할 수 있으므로, 빈은 반드시 무상태로 설계해야 한다. 톰캣의 스레드 풀 크기는 제한되어 있어 응답이 느린 API는 모든 스레드를 점유해 버리고 이후 요청은 대기하게 되므로, API 응답 속도가 곧 전체 처리량을 좌우한다. 이메일 발송처럼 즉시 응답이 필요 없는 작업은 비동기(@Async)로 별도 스레드 풀에 넘기고, 커넥션 풀링과 무상태 설계 같은 원칙을 지키는 것이 동시성 문제를 막는 핵심이라고 정리한다.
