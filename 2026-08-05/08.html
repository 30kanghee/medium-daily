What Happens When Multiple Users Hit Your API at the Same Time?

Gain Java Knowledge · 4 min read · 원문 보기 (Medium)

요약

서버 하나가 수천 명의 요청을 동시에 받아내는 비밀은 결국 스레드에 있다.

스프링 부트 API에 여러 사용자가 동시에 요청을 보낼 때 내부에서 실제로 무슨 일이 벌어지는지 스레드 관점에서 쉽게 풀어낸 글이다. 내장 톰캣 서버가 요청마다 스레드를 하나씩 배정하는 과정을 레스토랑의 웨이터 비유로 설명한다. 컨트롤러나 서비스, 리포지토리는 요청이 아무리 많아도 새로 만들어지는 게 아니라 싱글톤으로 딱 하나만 존재하며 여러 스레드가 이를 공유한다는 점을 강조한다. 이 싱글톤 빈이 상태값을 갖고 있으면 동시 접근 시 값이 꼬이는 레이스 컨디션이 발생할 수 있음을 카운터 예제로 보여주고, 결국 싱글톤 빈은 무상태로 설계해야 한다는 원칙으로 마무리한다.
